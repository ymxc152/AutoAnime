# 开发环境与构建部署

## 功能背景
本项目为 Python 包 + 双轨入口，按命令触发执行。推荐入口 `AutoAnimeMv2.py` 调用模块化 `autoanime/` 包；旧入口 `AutoAnimeMv.py` 保留兼容。当前版本新增了 dry-run、回滚、命名模板、Schema v2 多子文件缓存与 AI 失败回退链路，部署时需额外关注日志目录、缓存目录与环境变量。

## 功能目标
- 提供可复现的本地开发和运行步骤。
- 明确 API 密钥/Token 的环境变量注入方法。
- 给出最小化部署成本的执行方案。

## 功能边界
- 不包含容器编排或云端服务部署方案。
- 不负责第三方 API 账号申请与额度管理。

## 配置准备
1. 复制 `config.ini.Template` 为 `config.ini`（本地文件，不提交仓库）。
2. 默认 AI 已启用并优先，关键配置如下：
   - `USEOPENAIAPI = True`
   - `OPENAI_PRIORITY_FIRST = True`
   - `OPENAI_IDENTIFY_ALL = True`（启用后由 AI 直接识别剧名/季/集）
   - `OPENAI_BASE_URL = https://api.longcat.chat/openai`
   - `OPENAI_MODEL = LongCat-Flash-Chat`
   - `OPENAI_FALLBACK_ON_FAILURE = True`（AI 失败时默认回退本地规则 + 传统 API）
3. 推荐通过环境变量注入认证信息：
   - Windows PowerShell：`$env:OPENAI_API_KEY="你的key"`
   - Windows PowerShell：`$env:TMDB_BEARER_TOKEN="你的tmdb_token"`
   - Linux/macOS：`export OPENAI_API_KEY="你的key"`
   - Linux/macOS：`export TMDB_BEARER_TOKEN="你的tmdb_token"`
4. 新增行为配置：
   - `NAMING_STYLE = default|emby`
   - `DRY_RUN = True|False`
   - `USELINK = True|False`（默认 `True`，便于 qBittorrent 持续做种）
   - `STRICT_MODE = True|False`（默认 `True`，硬链接失败不降级移动）
   - `LINKFAILSUSEMOVEFLAGS = True|False`（默认 `False`，硬链接失败后是否降级为移动）
   - `MANDATORYCOVER = True|False`（默认 `True`，目标已存在是否允许覆盖）
   - `OUTPUT_PATH = 目标目录`（可留空，默认输出到当前扫描目录）
   - `CACHE_DIR` / `CACHE_TTL_SECONDS`
   - `CACHE_FLUSH_INTERVAL_SECONDS`
   - `OPERATION_LOG_ENABLE` / `OPERATION_LOG_DIR`
   - `MAX_FILENAME_LENGTH`（默认 `180`，单路径组件最大长度）
   - `SEEPSINGLECHARACTER = True|False`（默认 `False`，季/集不补零）
   - `USEBGMAPI = True|False` / `USETMDBAPI = True|False` / `USEBANGUMIAPI = True|False`（回退数据源开关）

## 运行方式
| 模式 | 命令示例 | 说明 |
| --- | --- | --- |
| 本地批处理 | `python AutoAnimeMv2.py "待整理目录"` | 扫描目录内番剧文件并整理 |
| 单文件整理 | `python AutoAnimeMv2.py "视频文件路径"` | 自动拆目录+文件名，并收集同目录字幕 |
| 目录+指定文件 | `python AutoAnimeMv2.py "待整理目录" --file "文件名"` | 在目录中仅整理指定文件 |
| QB 下载回调 | `python AutoAnimeMv2.py "%D" "%N" 1` | 由 qBittorrent 任务完成后触发；`.!qB` 等未完成临时文件会自动跳过 |
| Dry-run 预览 | `python AutoAnimeMv2.py "待整理目录" --dry-run` | 仅输出和记录操作，不移动文件 |
| Emby 命名 | `python AutoAnimeMv2.py "待整理目录" --naming-style emby` | 输出 `剧名 - S01E01` 风格命名 |
| 指定输出目录 | `python AutoAnimeMv2.py "待整理目录" --output-path "目标目录"` | 扫描源目录并整理到指定目标目录 |
| 链接开关 | `python AutoAnimeMv2.py "待整理目录" --use-link/--no-link` | 强制启用或禁用硬链接 |
| 严格模式 | `python AutoAnimeMv2.py "待整理目录" --strict-mode true/false` | 控制硬链接失败时是否允许降级移动 |
| 回滚模式 | `python AutoAnimeMv2.py rollback --log "操作日志路径"` | 依据日志逆序回滚 move/link 操作 |

> **旧入口兼容**：以上命令中的 `AutoAnimeMv2.py` 均可替换为 `AutoAnimeMv.py`，行为基本一致，但旧入口不支持单文件快捷输入。

## 部署要点
- 建议将脚本与 `config.ini` 放在固定目录，便于下载器调用。
- 若启用代理，确保 `USEPROXY/USESYSPROXY` 与代理地址匹配。
- 若使用硬链接，目标目录需与源文件位于同一文件系统并支持硬链接。
- 若硬链接模式下目标文件已存在，程序会默认保留原有目标文件，不用新的重复资源替换旧硬链接。
- 当重复资源被保留跳过后，程序会将该新资源的最终识别结果写入本地缓存，降低后续重复运行时的 AI/API 识别开销。
- 若 `OUTPUT_PATH` 与扫描目录不同，且启用了硬链接保留源文件，程序会在目标文件已与源文件指向同一物理文件时自动跳过重复整理。
- 若 `OUTPUT_PATH` 位于扫描目录内部，扫描阶段会自动忽略输出子树，避免把已整理结果再次扫入。
- 建议将 `CACHE_DIR` 与 `OPERATION_LOG_DIR` 放在可长期保留的位置，便于复跑提速与回滚。
- **缓存升级**：首次运行 `AutoAnimeMv2.py` 时，若检测到旧版 `api_cache.json`，会自动将其归档到 `CACHE_DIR/backups/` 并启用 Schema v2 多子文件缓存（`organization.json` / `titles.json` / `api_responses.json` / `cache_meta.json`），通常无需手动清理。

## 常见安全约束
- `config.ini` 可能包含敏感配置，应只保存在本地并加入忽略列表。
- 不在 README、代码、提交记录中写入真实 API Key/TMDB Token。
- 日志已对 key/token/secret/password 相关配置做脱敏。
