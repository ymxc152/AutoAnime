# AutoAnime v3 架构与运行链路

## 1. 单一实现、两个入口

项目只保留核心包 `autoanime_v3/`。日常使用是：

| 入口 | 作用 |
| --- | --- |
| `AutoAnimeWeb.py` | FastAPI + 静态 `webui/dist`，默认 `http://127.0.0.1:8765` |
| `AutoAnimeWorker.py` | 领取 `scan` / `execute_plan` / `rollback_operation`，跑定时与目录监听 |
| `AutoAnimeMv3.py` | CLI 一次性预览/执行；默认库 `.autoanime-v3/library.sqlite3` |

Web 默认数据目录是 `C:\ProgramData\AutoAnime`（库文件 `data/library.sqlite3`）。**Web 与 CLI 不自动共享缓存。**

生产控制台由 FastAPI 托管已构建的 `webui/dist`。Vite `5173` 不是生产入口。

## 2. 模块职责

```text
识别与整理核心（CLI 与 Worker 共用）
├─ scanner          输入扫描、季度文件夹/单文件、未完成下载过滤
├─ parser           文件名、目录上下文、季集、电影/特殊项、发布源
├─ catalog          别名、季度布局、特殊项默认值；TitleCatalog.version 使旧识别失效
├─ identify         IdentifyAgent 批量识别（生产路径）
├─ identify_units   按文件夹/作品聚类工作单元
├─ organize         OrganizeAgent：group_work_units → resolve_unit → remember → build_plan
├─ resolver         证据合并、置信度与安全阈值；resolve() 委托 resolve_unit
├─ planner          唯一目标路径、同集多版本、字幕计划、冲突检查
├─ executor         link/copy/move、批次自动回滚、JSONL 日志
├─ aiparse / review 单文件 AI 解析与审核辅助（测试与降级；生产扫描走 IdentifyAgent）
└─ services/memory  learned_show_memory 覆盖层（不经 RuleService.activate）

Web / Worker
├─ db/schema.py     SCHEMA_VERSION 5
├─ jobs/            持久队列、租约 Worker
├─ api/app.py       /api/v1 与 /health/live|/health/ready
└─ services/        profiles、scans、plans、operations、agent_chat、webhooks…
```

OrganizeAgent **禁止**生成 destination；`planner.build_plan` 是唯一目标路径来源。

## 3. 决策模型

识别结果只有同时满足以下条件才会进入可执行整理计划：

1. 标题存在，且来自中文文件名、受信别名目录、已学习记忆或通过本地校验的远程 agent；
2. 季度和集数完整（电影等类型按自身规则）；
3. 明确季集不能与远程 agent 冲突；
4. 置信度达到方案的 `min_confidence`；
5. 目标路径不覆盖已有不同文件。

所有证据写入识别结果。别名、季度布局或特殊项默认值变化时，`TitleCatalog.version` 进入决策指纹，旧结果自动失效。`learned_show_memory` 是覆盖层，**不会**在扫描中调用 `RuleService.activate`。

## 4. 季集规则

- 明确 `S03E02`、`Season 3 - 02`、`第三季 - 02` 优先。
- 文件只给绝对集数时，根据受控季度布局换算。
- 文件同时给季度和绝对集数时，仅在集数超过该季度合理范围且能唯一换算时处理。
- PV、TVSP、OVA 等没有集号的单文件必须在 `episode_defaults` 显式声明，不能全局默认成 E01。
- 未知英文标题不会因为“集数看起来正常”而自动整理。

## 5. 文件计划与执行

- 先解析所有文件，再一次性生成完整计划。
- 同一番剧、季度、集数的多个发布版本加入平台、字幕组、V2、无修或配音标签。
- 版本标签由文件自身元数据稳定决定；没有可识别发布信息时使用基于规范化源路径的 `version-xxxxxxxx`。
- 目标已存在时不覆盖。
- copy/move 写入失败时清理未完成目标。
- move 先把源原子重命名为同目录 `.partial` staging；复核后只删除 staging。
- CLI 默认仅预览；`--apply` 才执行。
- Web 路径：Worker 执行已批准（或 `auto_apply_safe` 入队）的计划；批次失败逆序回滚。
- 每项操作同时写 JSONL（CLI）或 `operation_batches` / `operation_items`（Web）。

## 6. Web 资料库 vs CLI 缓存

Web 使用 Schema v5：`storage_roots`、`scan_profiles`、`jobs`、`review_items`、`plans`、`file_locations`、`learned_show_memory`、`agent_sessions` 等。一条扫描方案 = 一个 `source_root_id` + 一个 `library_root_id`。

CLI 仍使用 `.autoanime-v3/library.sqlite3` 风格的识别缓存（`shows` / `resolutions` / `operations`）。不要把两套库当成同一文件。

Web 扫描成功落库后，`ScanService` 会调用 `PlanService.auto_apply_safe`：仅当计划 `ready`、无未关闭审核、无 conflict、`risk_level` 属于 `{normal}` 时批准并 **入队** `execute_plan`。扫描进程不直接 `OperationService.execute`。

## 7. WebUI 接入

浏览器只打 `/api/v1`。文件变更只发生在 Worker：

```text
触发（qB webhook / 定时 / 手动 / watch）
  → JobQueue scan
  → OrganizeAgent
  → reviews + immutable plan
  → auto_apply_safe 或管理员批准
  → JobQueue execute_plan
  → OperationService.execute（默认无人值守为 hardlink）
```

识别出错时，待处理/资料库打开绑定会话（`kind=review|library`），LLM 提案字段仅允许 `title` / `media_type` / `season` / `episode` / `release_tag` / `aliases` / `reason`。禁止 destination / path / action。应用后走 `ReviewService.resolve` 或 `CorrectionService.apply`，并写入记忆。

资料库标题纠正、合并误命名作品、执行后回填 library 条目均已实现，不再是“仅预览、尚未写入”。
